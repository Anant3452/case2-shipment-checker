# Shipment booking and pre-flight checker

Describe a UK-to-EU shipment in plain language, or upload Bookings and Items sheets, and get every booking checked before it leaves. Lanes: UK (London, Manchester, Birmingham, Leeds) to Germany, France and the Netherlands. GBP only. No login, no cookies.

## Run locally
```bash
npm install
npm run build          # builds the UI into dist/
npm start              # http://localhost:3000
```
Optional: copy `.env.example` to `.env` and set `GEMINI_API_KEY` to use Gemini for the chat. Without a key the rule-based assistant runs.

## Deploy
Any Node host works (Render, Railway).
- **Build command:** `npm install && npm run build`
- **Start command:** `npm start`
- **Health check:** `GET /health`
- **Secrets:** set `GEMINI_API_KEY` as a host secret. Never commit it.
- **Node:** 20 or later.

## Architecture
1. Deterministic rules in `src/domain/` (pure functions, no I/O): R-01 to R-10, carrier ranking, status, confirmation.
2. Chat in `src/chat/`: Gemini extracts fields through tools; the server applies them and re-runs the checks; the model phrases the results.
3. Rule-based fallback in `src/chat/fallback.ts`, used when there is no key or a Claude call fails.
4. Upload in `src/upload/`: parses xlsx and csv, joins on Booking ID, reports bad cells with references.
5. Express API in `src/server/` (`/api/chat`, `/api/upload`, `/health`) serving the built React UI in `ui/`.
6. Config in `config/` (`dangerous-goods.json`, `scoring.json`, `app.json`). Carrier and rule data in `data/`, generated by `scripts/import-template.ts`.

## Rule map
| Rule | Severity | Brief | Where |
|---|---|---|---|
| R-01 | Red | HS code at least 6 digits (spaces, dots and dashes stripped) | `src/domain/rules.ts` `r01` |
| R-02 | Red | Declared value within 1% of Σ(qty × price) | `r02` |
| R-03 | Red | Units per carton × cartons = quantity | `r03` |
| R-04 | Red | Booking cartons = Σ item cartons | `r04` |
| R-05 | Red | Gross weight ÷ pallets ≤ carrier max per pallet | `r05`, `src/domain/carriers.ts` |
| R-06 | Red | No lithium, aerosols or flammable liquids (keyword list) | `r06`, `config/dangerous-goods.json` |
| R-07 | Amber | Gross weight ≥ Σ(unit weight × qty) | `r07` |
| R-08 | Amber | Warehouse needs a delivery appointment | `r08` |
| R-09 | Amber | Every item has a country of origin | `r09` |
| R-10 | Amber | Ready date not in the past | `r10` |
| DATA | Red | Missing or invalid fields | `checkFields` |

## Tests
```bash
npm test          # all suites
npm run typecheck
```
- **Unit (`test/unit/`):** each rule, pass and fail, the R-02 1% boundary, R-05 at zero pallets, ranking under every priority with tie-breaks, the Balanced worked example, and parsers (`about 3 pallets`, `1.2 t`, `£5.4k`, HS codes with spaces or dots, DD-MM-YYYY).
- **Chat (`test/chat/`):** the scripted pallets scenario, declines, messy input, and the Claude tool loop with a scripted client.
- **End to end (`test/e2e/`):** uploads the clean and planted-error fixtures through the API and asserts status and rule IDs per booking. The expected table is in the file.

Fixtures are in `test/fixtures/` and regenerate with `npm run make-fixtures`.

## Fallback
Without `GEMINI_API_KEY`, or if a Gemini call fails, the app answers with the rule-based slot-filler. The checks are the same. The UI shows which assistant answered.

## Limitations
The real template was not available when this was built, so the rate card is placeholder except the Carrier A UK → Germany row. See `DECISIONS.md`.
